# Game Design

## 1. コンセプト

Deep Factoryは、**採掘 × 工場自動化 × インクリメンタル**を中心にした、一人称視点の3Dシングルプレイゲームを目指す。

最初はプレイヤー自身が採掘・回収・運搬・売却を行い、ゲームが進むほど採掘機、搬送設備、加工設備などへ作業を置き換えていく。

重要なのは、単に数値だけが増えることではなく、**自分が手作業していた場所が実際の機械や設備で置き換わり、拠点の見た目と動きが成長していくこと**。

## 2. 基本体験

```text
自分で掘る
  ↓
鉱石を拾う
  ↓
売る
  ↓
道具・容量を強化する
  ↓
採掘機を買う
  ↓
採掘を自動化する
  ↓
搬送を自動化する
  ↓
精錬・加工する
  ↓
工場を拡張する
  ↓
新エリアを解放する
```

## 3. 視点・操作

- 3D一人称視点を基本とする
- キーボード + マウスを基本操作とする
- プレイヤーは世界内を歩き、対象へ照準を合わせて操作する
- 採掘、拾得、売却、機械設置などは可能な限り同じ操作体系へ寄せる
- 操作説明を大量の文章にせず、照準付近やHUDで必要な時だけ表示する

## 4. MVP時点の世界

最初は小さなテスト採掘エリアだけを作る。

配置するもの:

- プレイヤー開始地点
- 採掘可能な岩
- 鉱石ドロップ
- 売却端末または売却エリア
- アップグレード端末
- 小型採掘機を設置できる場所

巨大マップ、車両、NPC、マルチプレイはMVP対象外。

## 5. 最初の30分の目標

### 0〜5分

- 移動と視点操作を覚える
- 岩を掘る
- 鉱石を拾う
- 売却する
- 最初のアップグレードを購入する

### 5〜15分

- 採掘速度を上げる
- 所持容量を増やす
- 新しい鉱石または高価値鉱石を見つける
- 最初の小型採掘機を購入する

### 15〜30分

MVP後の拡張段階として、搬送・精錬への導線を作る。

- コンベア解放
- 自動搬送
- 精錬機
- 加工品による価値上昇
- 次エリア解放目標

## 6. 成長設計

プレイヤーの成長は、単純な倍率だけでなく「作業をやらなくてよくなる」ことで感じさせる。

例:

- ツルハシ強化 → 同じ岩を早く壊せる
- バッグ強化 → 売却所へ戻る回数が減る
- 採掘機 → 掘る作業をしなくてよくなる
- コンベア → 回収・運搬をしなくてよくなる
- 自動売却 → 売却へ持っていく必要がなくなる

## 7. 世界観

仮設定:

> 荒廃した惑星に降り立った採掘者が、地下資源と旧文明の設備を利用して巨大採掘基地を作る。

ただし、世界観は現段階では固定しすぎない。ゲームシステムを先に成立させ、ストーリーや固有名詞は後から調整できる構造を保つ。

## 8. 参考作品の扱い

Ore Factory Squadなどの採掘・自動化ゲームは、以下のような**体験設計**の参考にする。

- 手作業から自動化へ移る流れ
- 工場が拡張されていく視覚的な達成感
- 「次に何を作るか」が分かる目標設計
- 道具や設備の段階的な強化

一方で、名称、アセット、マップ、UI、文章、ゲームデータ、実装をそのままコピーしない。

## 9. UI方針

- 暗めのUIを基本にする
- 白く眩しい全面UIを避ける
- 常時表示は必要最低限
- 現在の所持金、所持量、現在の目標を優先
- 数字を大量に並べない
- 操作対象と操作方法をその場で分かるようにする
- 自動化の進行はUIだけでなく、世界内の機械や動きでも見せる

優先順位:

1. 操作性
2. 分かりやすさ
3. ゲームの気持ちよさ
4. 見た目
